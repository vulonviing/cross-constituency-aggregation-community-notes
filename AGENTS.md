# Repository Working Rules

This repository is one active, root-first project.

- Treat root `notebooks/`, `src/`, `data/`, `jobs/`, `figures/`, and `paper/`
  as the canonical 200k Representative pipeline.
- Do not introduce scale-selection directories or alternate active strategies.
- Production paths are fixed. Smoke output belongs only in `.artifacts/smoke/`.
- Downstream analysis uses Method-B reassigned clusters.
- Keep `scckn/` at the repository root. Reference papers live under
  `docs/papers/`.
- Large raw files, `data/master_full.parquet`, and the two oversized interim
  ratings files remain local/ignored. In this checkout the two interim
  ratings files are symlinks into the original source checkout; see
  "Large Local Data" in `README.md` before treating them as missing.
- Notebooks are the single source of truth. Jobs execute them for their data
  and figure side-effects. No executed notebook copies are produced or committed.
- Figure outputs go under `figures/notebook_figures/` (auto-generated by
  notebooks) or `figures/script_figures/` (manually produced). Do not write
  to `figures/paper/`.

Current execution and methodology are documented in `README.md`.

## HARD RULE — AI step logging

Every agent doing work in this repository MUST append one step entry to
`ai-usage/step_logs/STEP_LOG.md` after completing each meaningful unit of
work. This is mandatory and applies to every model/agent. Each entry records
the date, time, model used, a global continuous step number, a step title,
and rough bullet points of what was done. Append only — never rewrite or
renumber prior entries. See `ai-usage/README.md` for the exact format.

## HARD RULE — Active paper and figure folders

- The active paper working folder is `paper/03-07-2026-1550-edition/`.
  New manuscript work goes here. Earlier dated editions under `paper/` are
  historical (see `paper/README.md`).

## HARD RULE — Active paper writing style

- Write the active paper in clear B2-C1 academic English.
- Use American spelling and style throughout the manuscript.
- Keep sentences direct, precise, and readable; avoid overly ornate or
  unnecessarily complex phrasing.

## HARD RULE — Active paper prose: no formulaic patterns

Applies to active manuscript prose only (the active paper folder), not to
idea-notes, step logs, or code comments. This extends the writing-style rule
above.

Prohibited repetition within any single section:
- Do not open consecutive paragraphs or list items with the same syntactic
  frame (e.g., "Imagine…/Now imagine…", "This X…", "These Y…").
- Do not reuse one subject-verb frame as a crutch more than once in a passage
  (e.g., "the algorithm is impressed / is shocked / spikes…").
- Do not chain "Because X, it Y" causal templates across adjacent sentences.
- Do not spread one idea across multiple mechanical sentences
  ("It cannot X… Since it fails Y… it is left with only Z").
- Do not use signal-only transitions that add no information
  ("This directly connects to…", "These findings lead directly to…",
  "This X is not merely…").

Positive requirements:
- Vary sentence openings and sentence length across each passage.
- Every transition sentence must carry new content, not just announce a link.
- Prefer one claim per sentence; collapse restatements of the same point.
- Preserve the deliberate, lively explanatory voice. This rule targets
  repetition, not personality. Deliberately parallel, labeled structures
  (e.g., a description list of principles) are exempt.

Threshold and self-check (mandatory before marking any writing unit done):
- Re-read the edited passage. If any prohibited pattern recurs three or more
  times, rewrite until it does not.
- Confirm no two adjacent paragraphs or list items share an opener frame and
  no signal-only transition remains.
- Note in the STEP_LOG entry that this anti-formulaic self-check was run.

## HARD RULE — Planning-mode user decisions

- Do not use auto-resolution timers for user decision requests in this
  repository. If a user decision is requested, wait for an explicit answer
  unless the user has already authorized a default.
- In Plan Mode, every critical decision must be asked before it is locked into
  a plan. This includes scope, citation/source choices, examples or analogies,
  methodology framing, output locations, and repository rules.
- Do not finalize a plan while critical user choices are still unanswered.

## HARD RULE — Paper idea capture skill

- Paper-related ideas that come up during discussion must be handled through the
  repository-local `paper-idea-capture` skill.
- Before doing active paper work, check whether
  `ai-usage/skills/paper-idea-capture/SKILL.md` exists. If it exists, use it.
- If the skill is missing, recreate it inside this repository only. Do not
  install it into global Codex, Claude, OpenCode, or other agent directories.
  Use the canonical prompt below so every agent and every machine creates the
  same skill.
- If the current agent runtime does not support skills, read
  `ai-usage/skills/paper-idea-capture/SKILL.md` as a normal instruction file
  and follow it.
- The active paper idea-note folder is
  `paper/03-07-2026-1550-edition/idea-notes/`.
- Do not write idea notes automatically. When a promising paper idea appears,
  briefly propose saving it; write the markdown note only when the user
  explicitly asks or approves.
- Idea-note filenames must follow
  `YYYY-MM-DD-HHMM-title-slug.md`, using local time and a lowercase ASCII slug
  with hyphens.
